# Portfolio Sitemap — Week 1 sketch (text version)

Target reader: a technical co-founder at a seed-stage AI startup.
One action: **book 15 minutes to watch a model go notebook → live endpoint.**

The rule: every page must move that person from *landing* → *believing* →
*acting*. One project proves the claim; everything else is demoted so nothing
distracts from the booking CTA.

```
/  (Home)
   ├── Hero: "I ship ML systems end-to-end, not just notebooks."
   │        + one-line proof + CTA → /contact (calendar)
   ├── /work        (PROOF — the RAG case study, the only full case study)
   │   ├── System diagram: FastAPI → Lightning AI GPU server → endpoint
   │   ├── p50/p95 cold-start before/after table (the numbers, not claims)
   │   ├── The failure story: what broke, what I fixed, what it cost
   │   └── CTA right here: "Book 15 minutes to watch a model ship live"
   │   └── Other work (one line each, links only): sid.ai chatbot,
   │       AI Email Assistant SaaS, Object Detection & Segmentation,
   │       FlyRank + FDAI internships
   ├── /about       (short: 2–3 lines — who I am, why shipping is my focus)
   └── /contact     (the ONE action: calendar booking + email)
```

## Why each page earns its place

| Page | Job it does for the co-founder | Would removing it hurt? |
|---|---|---|
| **Home (hero)** | States the claim in one breath; routes to proof and to the call. | Yes — nothing would state the claim. |
| **Work → RAG case study** | The only proof that matters: diagram, p50/p95 table, failure story. This is where they believe. | Yes — this is the entire evidence. |
| **Other work (one-liners)** | Keeps the resume projects present without distracting; links only. | No — removable, but gives breadth without cost. |
| **About** | One short paragraph of trust (who's the person, why shipping). | Marginally — folded into Home if space is tight. |
| **Contact** | The single action: book 15 minutes. | Yes — there'd be nowhere to act. |

## Pages deliberately NOT included

- Full case studies for the other projects — they'd distract from the one claim.
- Blog — adds words, not proof of shipping.
- Skills cloud / tools list — a co-founder reads claims, not keyword tags.
- Testimonials — none are real yet; a fake one kills trust instantly.
- Services / pricing — too early and broad for one claim.

## Proof anchors required before this is "true"

- [ ] RAG case-study page exists (diagram + p50/p95 table + failure story, <2 min read)
- [ ] Other projects demoted to a one-line "other work" list
- [ ] Calendar booking CTA sits directly under the case study
